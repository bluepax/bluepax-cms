## 观察与后续事项（不影响 M1 验收）

- 后台的 403 / 404 错误页是 SvelteKit 默认的纯文本页面（没有菜单与样式），可在后续加一个后台错误页。
- 文章保存时在事务里用 `Promise.all` 并发查询同一个连接（`modules/posts/posts.ts` 的 `sharedOf`），pg 8 会打印弃用警告并
  排队执行，升级到 pg 9 会报错；应改为顺序查询，并检查其他在事务中使用 `Promise.all` 的地方。
  已由 `fix/transaction-queries` 修复：同样的问题还出现在保存路由模板时（`content/routes.ts` 的
  `publishedAddresses`）；这类读取改用 `@bluepax/db` 的 `allQueries`（连接池上并行、事务中顺序），
  数据库测试中同一连接上的重叠查询会直接失败。
- 仓库级 `THIRD_PARTY_NOTICES.md` 仍按 ADR 0015 延后；`CHANGELOG.md` 在第一个 `chore(release)` 提交中由 git-cliff 生成。

- 流程（第 11 章）：dev 上 `862217a chore(release): v1.0.0-beta.34`（git-cliff 生成 `CHANGELOG.md`，ci `45956119951` 与 codeql
  `45956119900` 通过）→ main 上 `git merge --no-ff dev` 得到 `41c1a17 swift(v1.0.0-beta.34): release the m1 skeleton as the first beta`
  （第一父提交 `a9edb1f`、第二父提交 `862217a`，已签名）→ 签名附注标签 `v1.0.0-beta.34`（`swift; first flight`）→
