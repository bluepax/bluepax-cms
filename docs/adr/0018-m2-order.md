# 0018 M2 的实施顺序

- 状态：已采纳（2026-11-28）
- 涉及：规范第 3 章（通用能力：状态、工作副本与版本、slug 与 301）、第 4 章（数据库：`drafts`、`revisions`、
  任务队列表、全文检索）、第 6 章（路由模板、Delivery 端点、Webhook 事件、健康检查）、第 9 章（容器与数据、接口与
  后台任务、备份与可观测）、第 12 章（验收标准）、第 13 章（M2 发布链路）

## 背景

第 13 章的 M2「发布链路」列出 seo（301、sitemap 数据、404 日志）、Webhook、工作副本、版本与回滚、定时发布、搜索、
备份七项，没有规定先后。M1 各项留给 M2 的事项分散在 ADR 0007–0015 与 [M1 验收记录](../acceptance/m1.md) 中。
这些事项之间有依赖：定时发布、Webhook 投递与日志清理都要后台任务；301、Webhook、定时发布与搜索都挂在“发布”上，
而工作副本会改变 pages 与 posts 的保存与发布路径。

## 决策

每项一个 `feature/*` 分支、一个子会话，按下表顺序进行；前一项合入 dev 之后再开下一项，同一时间只有一个分支改迁移
与发布路径。第 6 项与第 4、5 项不改同一批文件，经所有者同意可以并行。

| 顺序 | 分支（暂定）                   | 内容                                                                                                                                                                                                                                                                                                                                       | 依赖与理由                                                                                                                                                                                      |
| ---- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | `feature/jobs-backup`          | `packages/jobs` 与 pg-boss、`BLUEPAX_ROLES` 的 worker 角色（启动、优雅停止、心跳、失败退避重试）、每日备份（保留策略、后台下载与查看、恢复步骤）                                                                                                                                                                                           | 其余各项的任务都要队列。备份只依赖数据库，是最独立的任务，适合用来验证队列本身。见 [0019](0019-jobs-and-daily-backups.md)                                                                       |
| 2    | `feature/working-copies`       | 工作副本（`drafts`，共享字段 + 各语言字段）、版本快照（`revisions`，每条内容每种语言 50 个）与回滚（载入工作副本）、预览工作副本、发布时共享字段影响其他已发布语言的提示                                                                                                                                                                   | 第 3 章“线上数据只由发布写入”改变 pages 与 posts 的保存与发布路径。定时发布、自动 301、Webhook、搜索都挂在“发布”上，先把发布路径定下来，后面各项只接一次                                        |
| 3    | `feature/scheduled-publishing` | 定时发布（pages、posts，按语言）                                                                                                                                                                                                                                                                                                           | 需要 1 的延时任务与 2 的“从工作副本发布”（第 3 章“定时发布同样从工作副本发布”）                                                                                                                 |
| 4    | `feature/webhooks`             | Webhook 地址与密钥（“接入与 API”）、第 6 章事件表（`对象.事件`）、签名与投递 ID、投递任务（超时 10 秒，指数退避最多 8 次）、`webhook_deliveries`（保留 30 天）与手动重发、`@bluepax/cms-client` 的 `verifyWebhook()`、示例前台的接收端点                                                                                                   | 需要 1 做投递与重试；`content.*` 在 2、3 的发布、下线上触发。签名编码与去重在发送端和 `verifyWebhook()` 两侧一起定、一起测（ADR 0013）                                                          |
| 5    | `feature/seo`                  | 301 表（301 / 410、CSV 导入、折叠条链、拒绝环路）、改 slug 与路由模板时自动写 301（重放审计日志里的 `site.routes_change` 与 `*.slug_change`）、Event API（`events:write`，404 日志）、`/seo/*` 与 `/feed` 数据、全局默认 OG、robots 与站点验证标签（仅管理员）、日志保留清理任务、示例前台的 sitemap / robots / RSS / llms.txt 与 404 上报 | 2 之后 slug 只在发布时生效，自动 301 只需挂在发布上；`redirects.updated` 与 `content.deleted` 直接用 4 的 Webhook；404 日志与审计日志的保留期清理（第 13 章默认 90 天、365 天）用 1 的定时任务  |
| 6    | `feature/search`               | 翻译表的 `search_vector`（按语言选检索配置，阿拉伯文归一化）、pg_trgm、`GET /search` 与 SDK 方法                                                                                                                                                                                                                                           | 2 之后翻译表只存线上内容，“草稿不可搜”自然成立；搜索只改 pages、posts 的翻译表迁移与 Delivery 层                                                                                                |
| 7    | `feature/management-api`       | Management API（`/api/manage/v1`）、Management Token 与范围、`GET system/status`（数据库、worker 心跳、队列积压与失败任务、备份、磁盘、Webhook 成败数、已启用模块）                                                                                                                                                                        | 第 13 章 M2 一行没有写，但 ADR 0012 与 M1 验收记录（第 5c 条）已把它排在 M2；它汇总 1 的心跳与备份结果、4 的 Webhook 成败数，所以放在最后。源站检查 `POST …/storage/check` 属 M3，询盘读写属 M4 |

### M1 延后事项的归属

- 第 2 项：pages 与 posts 的草稿、版本与回滚（ADR 0009 的 `PageContent` + `writeContent`，ADR 0010 的 `PostContent`、
  `PostShared` + `writeContent` / `writeShared` 是接入点）；预览工作副本（ADR 0012，目前预览的是当前语言版本）。
- 第 3 项：pages 与 posts 的定时发布。
- 第 4 项：Webhook 地址与密钥（ADR 0012）；`site.updated`（ADR 0007）；`media.replaced`（ADR 0008；
  `media.origin_changed` 随 M3）；`content.*`（ADR 0009、0010）；`verifyWebhook()`（ADR 0013）；示例前台的接收端点
  （ADR 0014）。
- 第 5 项：改 slug 写 301、删除写 410（ADR 0009、0010，改 slug 已记入审计 `pages.slug_change`、`posts.slug_change` 等）；
  路由模板改动的 301、折叠条链、拒绝环路（ADR 0011）；sitemap / RSS / llms.txt 数据（ADR 0011 的 `publishedAddresses`、
  `absoluteUrl`）；`/feed`、`/seo/*`、Event API 与全局默认 OG 文字和分享图（ADR 0008、0012）；robots 与站点验证标签的
  编辑拒绝（M1 验收第 5c 条）；SDK 的 Event API、`/feed`、`/seo/*` 方法（ADR 0013）；示例前台的 sitemap、robots、
  RSS、llms.txt 与 404 上报（ADR 0014）。
- 第 6 项：翻译表的 `search_vector`（ADR 0009、0010）；SDK 的 `/search` 方法（ADR 0013）。
- 第 7 项：Management API 与 Management Token（ADR 0012）。

### 不在 M2 的相关事项

- 媒体衍生图改为后台任务（第 9 章“图片变体”、处理并发默认 2）：随 M3。R2 的双写、同步重试与回填也是任务，并且
  重写同一段上传管线；衍生图改成异步还会改变上传后的界面与 Delivery 接口里衍生图的可用时机，与 R2 一起改只改一次。
  M2 期间衍生图仍同步生成（ADR 0008）。
- 备份加密后同步到独立的私有 R2 桶（第 9 章）：随 M3 的 R2 驱动。
- 发送邮件（SMTP 重置密码、询盘通知，第 3、8 章）：随 M4 的 `inquiries`，届时邮件作为后台任务发送。
- 告警推送：v1 不做（第 13 章）。

## 影响

- 第 12 章中与 M2 有关的验收项按上表逐项在 [M2 验收记录](../acceptance/m2.md) 中记录，每项完成时补上自己的条目。
- 每项开工前重读规范主本中相关章节；本表只排顺序，不替代各项自己的 ADR。
- 顺序有变（例如所有者决定第 7 项移到 M3）时修改本条并注明日期。
