# 0006 实例配置文件与初始化向导

- 状态：已采纳（2026-11-24）
- 涉及：规范第 2 章、第 9 章（未初始化时跳转向导）、第 12 章（初始化与配置），`packages/presets`，
  `apps/cms/src/lib/server/instance.ts`，`apps/cms/src/routes/setup`

## 背景

规范要求实例可由初始化向导或部署仓库中的 YAML 配置文件初始化，导出的配置与配置文件格式相同、
能在空库上无交互得到相同的实例；导入只在初始化时进行。规范只列出配置分组，没有规定文件格式与环境变量名。

## 决策

- 配置文件格式由 `packages/presets` 的 `instanceConfigSchema` 定义（Zod），带 `version: 1`；未知键报错，
  拼写错误不会被静默忽略。示例见 `examples/config/corporate.yaml`、`blog.yaml`。
- 已实现的分组：站点（类型、名称、时区、发布者类型）、语言（内容语言及书写方向、主语言、管理界面语言）、
  前台基础 URL、启用的可选模块、可用区块、存储模式（仅本地）。路由模板、保留 slug、目录、询盘、文章、
  运营等分组随对应模块加入同一格式。
- 每个分组存为 `settings` 表的一行（键名即分组名），模块开关存于 `instance_modules`；`settings.instance`
  记录初始化时间、来源（wizard / config-file）与预设，它的插入就是初始化的锁，重复初始化会失败。
- 安装口令：环境变量 `BLUEPAX_INSTALL_TOKEN`（至少 16 位），向导按 IP 限速（10 次 / 10 分钟），口令错误写入
  操作日志。配置文件：环境变量 `BLUEPAX_CONFIG_FILE`，启动时若实例未初始化则据此初始化，已初始化则忽略。
- 向导三种状态：未初始化 → 完整向导（初始化与首个管理员在同一事务中）；已由配置文件初始化但无管理员 →
  只创建首个管理员；已有管理员 → 向导永久关闭（访问 `/setup` 跳回首页）。未完成前，除 `/setup` 与
  `/api/health` 外的请求都跳转向导，`/api/*` 返回 503。
- 预设种子目前写入默认角色（编辑获得已启用模块的内容权限点）；区块定义、默认归属规则、默认文章分类
  随拥有它们的模块加入。

## 影响

- 部署仓库只需保存配置文件；后台“设置 → 实例配置”的导出页面随 site 模块提供（导出函数已实现并有往返测试）。
- 以后新增配置分组时同步更新 schema、示例配置与本记录，旧配置文件缺少新分组时由各模块给出默认值。
